# 个人信息管理器 — 开发步骤与规划文档

## 1. 开发总览

### 1.1 开发周期

| 阶段 | 名称 | 任务数 | 文件数 | 状态 |
|------|------|--------|--------|------|
| 阶段一 | 基础设施与主窗口骨架 | 5 | 7 | 待开发 |
| 阶段二 | 个人档案模块 | 4 | 3 | 待开发 |
| 阶段三 | 技能管理 + 状态管理 | 8 | 6 | 待开发 |
| 阶段四 | 知识管理模块 | 8 | 3 | 待开发 |

### 1.2 开发顺序依赖

```
阶段一 (基础设施)
    │
    └── 阶段二 (个人档案) ── 验证全链路模式
            │
            ├── 阶段三 (技能管理) ── 验证列表+CRUD模式
            ├── 阶段三 (状态管理) ── 可并行开发

                            │

```

### 1.3 开发约定

- 每个阶段完成后运行 `python main.py` 验证功能可用
- 每完成一个任务提交一次 git commit
- 所有类名使用 PascalCase，文件名使用 PascalCase，函数名使用 snake_case
- 每个 `__init__.py` 只做 re-export，不写业务逻辑
- Model 层使用 `@dataclass`，不引入任何方法逻辑

## 2. 阶段一：基础设施与主窗口骨架（任务 1.1 ~ 1.5）

**目标**：搭建项目目录骨架，实现可运行的空主窗口（左侧导航栏 + 右侧空白内容区 + 底部状态栏）。

### 任务 1.1 — 创建目录结构

**操作**：创建所有空目录和空的 `__init__.py` 文件。

| 产出文件 | 说明 |
|----------|------|
| `Core/__init__.py` | 空 |
| `Models/__init__.py` | 空 |
| `Services/__init__.py` | 空 |
| `Views/__init__.py` | 空 |
| `Tests/__init__.py` | 空 |

### 任务 1.2 — 实现 Core/Config.py

**职责**：定义项目所有路径常量和初始化函数。

| 产出文件 | 说明 |
|----------|------|
| `Core/Config.py` | 路径配置 |

**实现要点**：
```
- BASE_DIR: 项目根目录（main.py 所在目录）
- DATA_DIR: Data/ 目录路径
- BOOKS_DIR: Data/books/ 目录路径
- BACKUP_DIR: Data/backups/ 目录路径
- PROFILE_PATH, STATUS_PATH, SKILL_PATH 等各 JSON 文件路径常量
- ensure_directories(): 首次运行时创建 Data/、Data/books/、Data/backups/ 目录
- 通过 os.path 获取 BASE_DIR，不硬编码路径
```

### 任务 1.3 — 实现 Core/Exceptions.py

**职责**：定义所有自定义异常类。

| 产出文件 | 说明 |
|----------|------|
| `Core/Exceptions.py` | 异常层次 |

**实现要点**：
```
- PIMException(Exception)          # 基础异常
- DataLoadError(PIMException)      # 数据加载失败
- DataSaveError(PIMException)      # 数据保存失败
- RecordNotFoundError(PIMException)# 记录未找到
- ValidationError(PIMException)    # 数据校验失败
- BackupError(PIMException)        # 备份恢复失败
```

### 任务 1.4 — 实现 Core/Storage.py

**职责**：通用 JSON 文件存储类，提供 CRUD 操作。

| 产出文件 | 说明 |
|----------|------|
| `Core/Storage.py` | JSON 文件存储 |

**实现要点**：
```
- __init__(self, file_path): 接收文件路径，若文件不存在则创建空数组文件
- _load() -> list[dict]: 读文件返回字典列表，JSON解析失败返回空列表并打印警告
- _save(data: list[dict]): 原子写入（写 .tmp 再 os.replace）
- get_all() -> list[dict]: 返回所有记录
- get_by_id(record_id) -> dict|None: 按 ID 查单条
- query(**filters) -> list[dict]: 按字段名=值筛选
- add(record: dict): 自动添加 id(uuid4) 和 created_at 后追加保存
- update(record_id, updates: dict) -> bool: 更新字段并保存，自动更新 updated_at
- delete(record_id) -> bool: 删除记录并保存
- count() -> int: 返回记录总数
```

**验收标准**：能创建 JSONFileStorage 实例，调用各方法读写 Data/ 目录下的 JSON 文件。

### 任务 1.5 — 实现主窗口骨架

**职责**：创建可运行的 Tkinter 主窗口，包含导航栏、内容区和状态栏。

| 产出文件 | 说明 |
|----------|------|
| `Views/App.py` | 主窗口 |
| `Views/NavFrame.py` | 左侧导航栏 |
| `main.py` | 程序入口 |

**Views/NavFrame.py 实现要点**：
```
- NavFrame(tk.Frame): 左侧导航栏（固定宽度 ~140px）
- 使用 tk.Button 排列导航按钮（个人档案、状态管理、技能管理、知识管理、密码管理、数据管理、数据概览）
- 构造函数接收 on_select 回调函数
- 点击按钮时调用 on_select(page_name)，并高亮当前选中按钮
- 按钮样式：flat、左对齐、足够高度便于点击
```

**Views/App.py 实现要点**：
```
- App 类
- __init__: 创建 Tk 根窗口，标题"个人信息管理器 (PIM)"
  默认窗口大小 960×640，最小 800×500
- 创建状态栏 Label（sunken 效果，锚点 W）
- 创建 NavFrame（左侧 pack）
- 创建内容区 Frame（右侧 pack，fill=BOTH, expand=True）
- _init_pages(): 创建各页面占位 Frame（均为空白 Frame，后续阶段替换）
- _switch_page(page_name): 切换内容区显示的页面
- run(): 启动 mainloop
```

**main.py 实现要点**：
```
- from Views.App import App
- from Core.Config import ensure_directories
- if __name__ == "__main__":
    ensure_directories()
    app = App()
    app.run()
```

**验收标准**：运行 `python main.py`，出现窗口，左侧 7 个导航按钮可点击切换（内容区暂为空白占位），底部显示状态栏"就绪"。

## 3. 阶段二：个人档案模块（任务 2.1 ~ 2.4）

**目标**：打通 Model → Service → View 全链路，实现个人档案的查看和编辑。

### 任务 2.1 — 实现 Profile 数据模型

| 产出文件 | 说明 |
|----------|------|
| `Models/Profile.py` | Profile 数据类 |

**实现要点**：
```
- @dataclass Profile
- 字段全部带默认值：name, gender, birthday, phone, email, address, wechat, qq, github, blog, bio, created_at, updated_at 均为空字符串
```

### 任务 2.2 — 实现 ProfileManager 业务逻辑

| 产出文件 | 说明 |
|----------|------|
| `Services/ProfileManager.py` | 档案管理 |

**实现要点**：
```
- 构造函数: self.data_path = PROFILE_PATH（从 Config 导入）
- 注：Profile 是单例数据（一份 JSON 对象），不使用 JSONFileStorage 的列表模式
- _load() -> dict: 从文件加载档案字典（文件不存在返回空字典）
- _save(data: dict): 保存档案字典到文件（原子写入）
- get_profile() -> Profile: 加载并返回 Profile 对象
- update_profile(**kwargs) -> Profile: 更新字段并保存，返回更新后的 Profile
- export_profile(output_path: str): 导出档案为独立 JSON 文件
- get_summary() -> dict: 返回档案完整性统计（已填字段数/总字段数）
```

### 任务 2.3 — 实现 ProfilePage 页面

| 产出文件 | 说明 |
|----------|------|
| `Views/ProfilePage.py` | 个人档案页面 |

**实现要点**：
```
- ProfilePage(tk.Frame)
- 构造函数接收 (parent, status_bar)
- 左侧：字段标签列表（姓名、性别、生日、...）
- 右侧：对应 Entry 输入框，预填已有数据
- 对于 bio/简介字段使用 Text 多行输入
- gender 使用 ttk.Combobox（选项：男/女/其他）
- [编辑/保存] 按钮：切换编辑模式（Entry 从 readonly 变为 normal）
- [导出] 按钮：调用 filedialog.asksaveasfilename + ProfileManager.export_profile()
- refresh(): 从 ProfileManager 重新加载数据显示
- 保存时调用 ProfileManager.update_profile()，并在状态栏显示"档案已保存"
```

**验收标准**：窗口切换到个人档案页面，能看到表单字段，可编辑并保存，可导出 JSON 文件，状态栏有操作反馈。

### 任务 2.4 — 集成到主窗口

**操作**：修改 `Views/App.py` 的 `_init_pages()`，将 ProfilePage 替换空白占位。

**产出**：修改 `Views/App.py` 少量代码。

**验收标准**：运行 `python main.py`，点击"个人档案"显示完整表单页面，数据可编辑保存，重启程序后数据持久化。

**目标**：实现知识管理页面，包含文本笔记和 PDF 电子书两个 Tab，验证 ttk.Notebook + 文件导入模式。

### 任务 4.1 — 实现 KnowledgeItem 数据模型

| 产出文件 | 说明 |
|----------|------|
| `Models/Knowledge.py` | KnowledgeItem 数据类 |

**实现要点**：
```
- @dataclass KnowledgeItem
- 字段：id="", item_type="note", title="", category="", keywords=field(default_factory=list), content="", file_path="", file_size=0, created_at="", updated_at=""
```

### 任务 4.2 — 实现 KnowledgeManager 业务逻辑

| 产出文件 | 说明 |
|----------|------|
| `Services/KnowledgeManager.py` | 知识管理 |

**实现要点**：
```
- 构造函数: self.storage = JSONFileStorage(KNOWLEDGE_DATA_PATH)
- 确保 Data/books/ 目录存在

# 通用
- get_all(item_type=None) -> list[KnowledgeItem]: 按类型筛选
- get_by_id(item_id) -> KnowledgeItem|None
- get_by_category(category, item_type=None) -> list[KnowledgeItem]
- search(keyword) -> list[KnowledgeItem]: 标题 + 关键词 + 内容 模糊匹配
- get_all_categories(item_type=None) -> list[str]
- get_all_keywords() -> list[str]: 去重返回所有已用关键词
- delete_item(item_id) -> bool: 删除记录 + 若为电子书则删除 PDF 文件
- get_statistics() -> dict: {total_notes, total_ebooks, by_category, all_keywords}

# 笔记
- create_note(title, category, keywords, content) -> KnowledgeItem
- update_note(note_id, **updates) -> bool

# 电子书
- import_ebook(source_path, title, category, keywords) -> KnowledgeItem:
  1. 校验文件是否为 PDF（检查前 4 字节是否为 %PDF）
  2. 生成目标文件名（使用 uuid 避免冲突）
  3. shutil.copy2 复制到 Data/books/
  4. 获取 file_size
  5. 创建 KnowledgeItem(item_type="ebook") 并保存

- update_ebook_info(ebook_id, **updates) -> bool:
  只更新元数据（title, category, keywords），不涉及文件

- open_ebook(ebook_id):
  获取 PDF 绝对路径，调用系统默认程序打开
  Windows: os.startfile(path)
  macOS: subprocess.run(["open", path])
  Linux: subprocess.run(["xdg-open", path])

- get_ebook_file_path(ebook_id) -> str|None:
  返回 PDF 文件的绝对路径
```

```
- search(keyword) -> list[PasswordEntry]:
  按 platform + url + username 模糊匹配

- get_decrypted_password(entry_id) -> str:
  获取明文密码（从存储中取出后 _decode）

- update_entry(entry_id, **updates) -> bool:
  如果 updates 包含 password 字段，自动 _encode

- delete_entry(entry_id) -> bool

- count() -> int
```

## 9. 风险与应对

| 风险 | 影响 | 应对措施 |
|------|------|----------|
| Tkinter 跨平台样式不一致 | UI 美观度 | 使用 ttk 主题控件，优先保证功能正确 |
| PDF 文件过大导致复制耗时 | 导入体验 | 异步复制 + 进度提示（后续优化），首版同步复制 |
| base64 不够安全 | 密码泄露 | 文档中标记为"首版简化方案"，后续升级 AES |
| JSON 文件损坏 | 数据丢失 | 原子写入 + 解析失败时备份原文件 |
| 大文件备份耗时 | 备份体验 | 首版全量同步备份，后续可加增量备份 |
