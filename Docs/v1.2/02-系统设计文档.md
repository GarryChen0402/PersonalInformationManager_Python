# 个人信息管理器 v1.2 — 系统设计文档

## 1. 设计原则（延续 v1.1 + 新增）

| 原则 | 说明 |
|------|------|
| 模块化 | v1.1 架构不变，新增模块遵循同一 Model → Service → View → Storage 模式 |
| 零外部依赖 | 新增功能均使用标准库实现（`hashlib`/`hmac` 做认证加密，`calendar`/`datetime` 做日历逻辑） |
| 关注点分离 | 四层分离不变，热力图归属 ChartWidgets，日历组件归属 Widgets |
| 向后兼容 | v1.1 数据自动识别，加密格式版本化支持渐进升级 |
| 配置扩展 | config.json 向后兼容新增字段，缺失字段使用默认值 |
| 测试优先 | 共享测试基类减少重复，新增模块 TDD 开发 |

## 3. 加密安全升级设计

### 3.1 当前方案回顾（v1.1）

```
加密: PBKDF2(salt) → 密钥 → SHA-256 CTR 流密钥 → XOR → base64(salt + nonce + ciphertext)
问题: 无消息认证，密文可被篡改而不被检测
```

### 3.2 升级方案：Encrypt-then-MAC（v1.2）

```
加密流程:
  1. PBKDF2(salt, password, 100000) → 32 字节 AES 密钥 + 32 字节 HMAC 密钥（共 64 字节派生）
  2. secrets.token_bytes(16) → nonce
  3. SHA-256 CTR 流密钥 → XOR 加密 → ciphertext
  4. HMAC-SHA256(hmac_key, nonce + ciphertext) → 32 字节签名
  5. 存储格式: "v2:" + base64(salt + nonce + ciphertext + signature)

解密流程:
  1. 检查版本头 "v2:"，无版本头视为 v1 格式
  2. base64 解码 → salt(16) + nonce(16) + ciphertext + signature(32)
  3. PBKDF2 派生密钥
  4. HMAC-SHA256(hmac_key, nonce + ciphertext) 验证签名
  5. 签名不匹配 → 抛出 CryptoError("密文已被篡改或密码错误")
  6. 签名匹配 → 重建密钥流 → XOR 解密
```

### 3.3 SimpleCrypto 接口变更

```python
class SimpleCrypto:
    VERSION_V1 = "v1"    # 无 HMAC（向后兼容）
    VERSION_V2 = "v2"    # 有 HMAC

    @staticmethod
    def derive_keys(master_password: str, salt: bytes) -> tuple[bytes, bytes]:
        """PBKDF2 派生 64 字节，前 32 字节为加密密钥，后 32 字节为 HMAC 密钥。"""

    @staticmethod
    def encrypt(plaintext: str, master_password: str, version: str = "v2") -> str:
        """加密，默认 v2 格式（含 HMAC）。"""

    @staticmethod
    def decrypt(encoded: str, master_password: str) -> str:
        """解密，自动识别 v1/v2 格式。v2 先验证 HMAC。"""

    @staticmethod
    def create_token(master_password: str) -> str:
        """创建验证令牌（v2 格式加密固定字符串）。"""

    @staticmethod
    def verify_token(master_password: str, token: str) -> bool:
        """验证令牌，自动处理 v1/v2 格式。"""

    @staticmethod
    def get_password_strength(password: str) -> dict:
        """评估密码强度，返回 {level: 'weak'/'medium'/'strong', score: 0-4}。"""
```

### 3.4 CryptoService 自动锁定设计

```python
class CryptoService:
    _master_password: str | None = None
    _auto_lock_timer: threading.Timer | None = None
    _failed_attempts: int = 0
    _lock_until: float = 0.0

    DEFAULT_TIMEOUT = 300  # 默认 5 分钟

    @classmethod
    def unlock(cls, master_password: str) -> bool:
        """验证密码，成功后启动自动锁定计时器，重置错误计数。"""

    @classmethod
    def _start_auto_lock_timer(cls):
        """根据配置的超时时间启动/取消 Timer。timeout=0 表示不自动锁定。"""

    @classmethod
    def _reset_auto_lock_timer(cls):
        """每次加密/解密操作后重置计时器（活跃则延后锁定）。"""

    @classmethod
    def lock(cls):
        """清除密码缓存，取消计时器。"""

    @classmethod
    def get_lock_status(cls) -> dict:
        """返回 {is_locked, failed_attempts, lock_remaining_seconds}。"""
```

### 3.5 密码迁移策略

```
PasswordManager.__init__:
  1. 加载密码数据
  2. 检测每条密码的加密格式版本头
  3. 若存在 v1 格式密码 → 标记 migration_pending = True
  4. 用户解锁后 → 提示"发现旧格式密码，建议立即升级"
  5. 用户确认升级 → 用 v2 格式重新加密所有密码
  6. 迁移完成 → 清除 migration_pending 标记
```

## 11. 设计决策记录

| 决策 | 选择 | 原因 |
|------|------|------|
| 加密升级方案 | Encrypt-then-MAC (HMAC-SHA256) | 业界标准做法；复用已有 SHA-256 原语；向前兼容 v1 格式 |
| 密文版本化 | 版本头前缀 "v1:"/"v2:" | 简单可靠；解密时一步判断版本；向前兼容 |
| 习惯打卡存储 | 习惯定义与打卡记录分离（两张表） | 遵循数据库范式；便于按年归档打卡数据；查询灵活 |
| 日记唯一键 | 日期为唯一键（同一天只存一篇） | 简化 UI 交互；符合日记场景直觉；日历导航无歧义 |
| 日历热力图 | Canvas 自绘矩形网格（非图片） | 零依赖；支持悬停交互；主题颜色可切换 |
| 导航栏折叠 | Canvas + 缩小为图标栏 | 为 9 个模块腾出空间；保留全部导航能力 |
| 表格排序 | 点击表头触发 Python `sorted()` | 零依赖；数据量小时（<1000 条）性能足够 |
| Markdown 导出 | YAML frontmatter + Markdown 正文 | 兼容 Obsidian/VS Code 等工具；人眼可读 |
| 自动锁定 | `threading.Timer` 单次定时器 | 简单可靠；每次操作后重置计时器；timeout=0 关闭 |
| 测试基类 | `PIMTestCase(unittest.TestCase)` 共享基类 | 消除 11 个测试文件中重复的 setUpClass/tearDownClass |
