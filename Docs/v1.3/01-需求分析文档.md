# 个人信息管理器 v1.3 — 需求分析文档

## 1. 版本概述

v1.2 已实现 9 个核心模块（个人档案、状态管理、技能管理、知识管理、待办事项、习惯追踪、日记、密码管理、数据备份恢复）+ 仪表盘 + 全局搜索 + Canvas 图表（折线/雷达/柱状/迷你/热力图）+ CSV/Markdown/iCalendar 导出，共计 70+ 功能点，249 项测试，零外部依赖。

v1.3 聚焦于 **GUI 框架迁移：从 Tkinter 迁移到 PySide6（Qt for Python）**。这是项目历史上最大的一次架构变更——View 层全面重写，但 Model、Service、Core 三层保持不变。

---

## 2. 升级方向

### 2.1 GUI 框架迁移：Tkinter → PySide6（P0）

Tkinter 作为 Python 标准库 GUI 工具包，在 v1.0~v1.2 期间满足了基本需求，但随着项目复杂度增长（9 个模块、6 种图表、5 套主题），其局限性日益显现：

- 外观老旧，无法与现代桌面应用媲美
- Treeview 功能有限（无内置筛选/多选/富文本）
- Canvas 自绘图表代码量大（ChartWidgets.py 763 行），维护成本高
- 布局管理（pack/grid）在复杂界面中力不从心
- 缺少现代 UI 组件（如 QStackedWidget、QSplitter、QTableView）

PySide6 是 Qt 6 的官方 Python 绑定（LGPL 协议），提供专业级桌面应用开发能力。

| 迁移项 | Tkinter 现状 | PySide6 目标 |
|--------|-------------|-------------|
| 主窗口 | `tk.Tk()` + 手动几何管理 | `QApplication` + `QMainWindow` + `QStackedWidget` |
| 导航栏 | `tk.Frame` 150px 固定宽 + 手动折叠 | `QToolBar` / `QListWidget` + `QSplitter` 拖拽调整 |
| 表格 | `ttk.Treeview` + 手动排序 | `QTableWidget` 内置排序 + 列宽自适应 |
| 图表 | `tk.Canvas` 自绘 (763 行) | `QPainter` 自绘（保留灵活性）或 `Qt Charts` 可选 |
| 标签页 | `ttk.Notebook` | `QTabWidget` |
| 对话框 | `tk.Toplevel` 模态窗 | `QDialog` 原生模态 |
| 布局 | `pack()`/`grid()` 手动布局 | `QVBoxLayout`/`QHBoxLayout`/`QGridLayout`/`QSplitter` |
| 文本编辑 | `tk.Text` | `QTextEdit` / `QPlainTextEdit` |
| 消息框 | `tk.messagebox` | `QMessageBox` |
| 文件对话框 | `tk.filedialog` | `QFileDialog` |
| 定时器 | `root.after()` | `QTimer` |
| 事件处理 | `bind()` + `command` | Qt Signals & Slots |
| 主题 | 手动字典映射 + 递归遍历 widget | Qt Stylesheet (`qApp.setStyleSheet()`) |

### 2.2 为什么选择 PySide6 而非 PyQt5/PyQt6

| 对比维度 | PySide6 | PyQt5 | PyQt6 |
|----------|---------|-------|-------|
| 协议 | LGPL | GPL | GPL |
| 商业使用 | 无需购买许可 | 需购买商业许可 | 需购买商业许可 |
| 维护方 | Qt 官方 (The Qt Company) | Riverbank Computing | Riverbank Computing |
| Qt 版本 | Qt 6.x | Qt 5.x | Qt 6.x |
| API 风格 | Pythonic (Snake case) | C++ 风格 (Camel case) | C++ 风格 (Camel case) |

**选择 PySide6**：LGPL 协议对学习项目友好；Qt 官方维护保证长期兼容性；Pythonic API 风格降低学习成本。

### 2.3 不迁移的部分（Core / Model / Service 三层不变）

迁移严格限定在 View 层。以下层次保持完全不变：

## 3. 非功能需求

| 需求 | 描述 |
|------|------|
| 引入外部依赖 | **首次引入外部依赖**：PySide6（LGPL 协议，`pip install pyside6`） |
| Python 版本 | 继续支持 Python 3.10+（PySide6 要求 ≥ 3.9） |
| 性能 | 启动时间 < 2s，页面切换 < 100ms，大数据列表渲染 < 500ms（1000 条） |
| 向后兼容 | v1.2 数据文件（JSON）完全兼容，无需迁移 |
| 平台支持 | Windows / Linux（PySide6 跨平台，macOS 理论支持但非目标） |
| 代码质量 | 重写后 View 层代码量减少约 10-15%（利用 Qt 内置能力） |
| 测试 | 现有 Service/Model 层测试（249 个）全部保持通过 |

## 4. 风险评估

| 风险 | 影响 | 概率 | 应对措施 |
|------|------|------|----------|
| 引入外部依赖 | 破坏"零依赖"原则 | 100% | 仅引入 PySide6 一个依赖（LGPL），在 README 中明确说明 |
| View 层完全重写 | 开发周期长，可能引入新 bug | 高 | 分阶段开发，每阶段完成后功能测试；保留 v1.2 Tkinter 分支 |
| 图表绘制复杂度 | QPainter 绘制 6 种图表需要学习成本 | 中 | 保持与 ChartBase 相同的接口设计；可参考 Tkinter Canvas 的绘制逻辑 |
| 主题系统重建 | Qt Stylesheet 语法与 Tkinter 手动配置完全不同 | 中 | Qt Stylesheet 更强大，5 套主题可更简洁地实现 |
| 键盘快捷键冲突 | Qt 与 Tkinter 事件处理机制不同 | 低 | Qt 有完善的 QShortcut 机制 |
| 打包分发 | PyInstaller 打包 PySide6 应用体积增大 | 低 | PySide6 的 PyInstaller 支持成熟，自动 hook |
| 学习曲线 | 开发者需学习 Qt 信号槽/布局/样式机制 | 中 | PySide6 API 设计 Pythonic，文档完善 |

## 5. 迁移前后对比

| 指标 | v1.2 (Tkinter) | v1.3 (PySide6) |
|------|---------------|----------------|
| 外部依赖 | 0 | 1 (PySide6) |
| View 层代码行数 | ~6,100 行 | ~5,000~5,500 行 |
| 主题实现 | 手动字典 + 递归遍历 (~120 行) | Qt Stylesheet (~80 行) |
| 表格排序 | 手动实现 (~50 行 BasePage) | Qt 内置 (0 行) |
| 窗口几何 | 手动保存/解析 geometry 字符串 | QMainWindow 原生支持 |
| 图表绘制 | Canvas 自绘 | QPainter 自绘（代码量相近） |
| 布局管理 | pack/grid 手动布局 | QLayout 自动布局 |
| 应用外观 | Tkinter 原生（跨平台不一致） | Qt 原生（跨平台一致且现代） |
| 启动速度 | ~0.5s | ~1.0s（Qt 初始化开销） |

## 8. 决策记录

| 决策 | 选择 | 原因 |
|------|------|------|
| 迁移目标 | PySide6 | LGPL 协议、Qt 官方维护、Pythonic API、Qt 6 最新版本 |
| 迁移范围 | 仅 View 层 | Core/Model/Service 三层不受影响，降低风险 |
| 图表实现 | QPainter 自绘（保留灵活性） | 不引入 Qt Charts 额外依赖；QPainter 功能与 Canvas 对等 |
| 主题实现 | Qt Stylesheet 全局样式表 | 比 Tkinter 手动配置更简洁强大 |
| 打包工具 | 继续使用 PyInstaller | PySide6 的 PyInstaller hook 成熟 |
| 版本分支 | v1.3 在新分支开发，v1.2 保留 | 可随时回退到 Tkinter 版本 |
